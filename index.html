Not connected — this is the recommended store for multi-device / audit use

Once connected, every change here saves to a Firestore document in your own Firebase project, and updates live on any other device/browser signed in to the same project — this is the persistent, audited backing store. A lightweight time-stamped entry is also written to an auditLog collection on every sync.

How to set this up (one-time, ~5 minutes)
  1. Go to the Firebase Console → Add project (free "Spark" plan is enough for this).
  2. In the project, go to Build → Firestore Database → Create database (start in test mode, then tighten the rules below).
  3. Go to Project settings (⚙ icon) → scroll to Your apps → click the Web (</>) icon → register an app (no hosting needed).
  4. Copy the firebaseConfig object shown (starts with apiKey) and paste the whole thing above.
  5. Important — security: Firestore's default "test mode" rules allow anyone with this config to read/write. Since only you should edit this data, go to Firestore → Rules and restrict access — e.g. require Firebase Authentication, or at minimum set an expiry and IP/App Check restriction. This app itself doesn't implement a login screen.
Not connected — data saved to this browser only

Once connected, everything you type here is saved automatically to a file named field-ops-tracker-data.json in your Google Drive. No server, no other users involved.

How to get a Client ID (one-time, ~3 minutes)
  1. Open Google Cloud Console → Credentials (create a project first if you don't have one).
  2. Click Enable APIs and Services → search for and enable the Google Drive API.
  3. Go to OAuth consent screen → set it to External → add your own Google account as a test user.
  4. Go to Credentials → Create Credentials → OAuth client ID → type Web application.
  5. Under Authorized JavaScript origins, add the exact address this page will be opened from (e.g. http://localhost:8000).
  6. Copy the Client ID and paste it above. Important: this file must be opened via http:// or https:// (e.g. by running a tiny local server) — not by double-clicking it — for Google sign-in to work.
